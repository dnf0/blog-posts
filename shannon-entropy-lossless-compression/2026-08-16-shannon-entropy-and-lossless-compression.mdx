At its core, lossless data compression is straightforward: symbols that appear frequently should take up fewer bits than symbols that appear rarely. In 1948, Claude Shannon formalised this intuition, establishing the mathematical foundation for modern digital communication and storage.

Whenever we transmit or store data—whether it is telemetry streamed from an Earth observation satellite, sensor logs from an edge device, or text across a network—we are dealing with sequences of discrete symbols. This post walks through Shannon's foundational source coding argument step by step, using clean diagrams and interactive simulators as a concise refresher.

## 1. The Fundamental Setup: Sequences, Counts, and Probabilities

Let us start with the exact premise laid out in classical information theory papers [1](#references):

> *"For the sake of simplicity, let us assume a finite set of data we wish to transmit, with each independent element indexed by i = 1 ... M. In a sequence of data of length N, we count the frequency nᵢ of data point xᵢ such that N = ∑ nᵢ or equivalently ∑ pᵢ = 1."*

![Figure 1: Incoming data sequence parsed into empirical frequencies and probability distributions.](/images/shannon/01_data_stream.png)

Let us unpack every variable in this statement:

1. **The Alphabet Size (M):** This is the number of distinct possible symbols in our universe. If we are recording weather states (Sunny, Cloudy, Rainy, Snowy), then *M = 4*.
2. **The Sequence Length (N):** This is the total number of observations or transmissions. (In Figure 1 above, we illustrate a sample stream of *N = 20*; below, we scale to *N = 100* for intuitive percentages).
3. **The Frequency Count (nᵢ):** How many times symbol *xᵢ* actually appeared in the sequence. For example:
   - Sunny (*n_sunny = 60*)
   - Cloudy (*n_cloudy = 25*)
   - Rainy (*n_rainy = 10*)
   - Snowy (*n_snowy = 5*)
4. **The Conservation Laws:**
   - **Sum of counts:** *∑ nᵢ = 60 + 25 + 10 + 5 = 100 = N*.
   - **Probabilities (pᵢ = nᵢ / N):** Converting counts to relative frequencies gives *p_sunny = 0.60*, *p_cloudy = 0.25*, *p_rainy = 0.10*, and *p_snowy = 0.05*.
   - **Sum of probabilities:** *∑ pᵢ = 0.60 + 0.25 + 0.10 + 0.05 = 1.00* (100%).

Every compression algorithm begins with this basic probability distribution.

## 2. Quantifying "Surprise": Why the Logarithm?

Before constructing compression schemes, we need a standard mathematical measure for the amount of information conveyed when a symbol *xᵢ* appears.

Intuitively, information is inversely related to probability:
* If an event is virtually guaranteed (e.g., *p ≈ 1.0*), observing it provides almost no new information—it has zero surprise.
* If an event is rare (e.g., *p = 0.01*), observing it resolves substantial uncertainty and carries high information.

Claude Shannon formalised this "self-information" (or surprise) of an outcome with probability *pᵢ* as [2](#references):

```text
I(xᵢ) = log₂(1 / pᵢ) = −log₂(pᵢ)
```

### What Exactly is a "Bit"?

Before exploring why logarithms appear, let us clarify the unit of measurement:
* **Etymology:** The term **bit** is a portmanteau of **"binary digit"** (coined by John Tukey and adopted by Claude Shannon in 1948).
* **Definition:** In information theory, **1 bit** is defined as the exact amount of information required to choose between **two equally likely outcomes** (such as a fair coin landing Heads vs. Tails, a single Yes/No decision, or switching a digital circuit between `0` and `1`).
* **Base Calibration:** When we use base-2 logarithms (`log₂`), information is measured in **bits**. (If we used natural logarithms `ln`, the unit would be *nats*; in base 10, *hartleys*). Because digital computers operate using two-state binary transistors (`0` and `1`), the base-2 **bit** is the natural physical currency of digital storage and transmission.

Why does the base-2 logarithm appear? There are two distinct, complementary reasons: one operational (binary decision trees) and one mathematical (the additivity requirement).

![Figure 2: Claude Shannon's concept of surprise: high probability conveys minimal information, while rare events carry substantial bit cost.](/images/shannon/02_surprise_meter.png)

### Reason 1: The Binary Decision Tree (Halving the Search Space)

Think of receiving information as playing the game of *20 Questions*. Each binary Yes/No question you ask divides the remaining candidate space in half:
* With **1 question** (1 bit), you can distinguish between *2¹ = 2* equally likely outcomes (`0` vs `1`).
* With **2 questions** (2 bits), you can distinguish between *2² = 4* outcomes (`00, 01, 10, 11`).
* With **b questions** (*b* bits), you can distinguish between *2ᵇ = M* outcomes.

To find how many bits *b* are needed to identify one specific outcome out of *M* equally likely possibilities, we invert the exponent:

```text
2ᵇ = M  ⟹  b = log₂(M)
```

Since each outcome has probability *p = 1/M*, we can rewrite *M* as *1/p*:

```text
b = log₂(1 / p) = −log₂(p)
```

The logarithm directly measures the **depth of the binary decision tree** required to isolate that outcome.

### Reason 2: Independent Clues Must Add Up (While Probabilities Multiply)

Consider what happens when you observe two completely independent events:
* **Event A:** A fair coin lands Heads (*p_A = 0.5*).
* **Event B:** A second fair coin lands Heads (*p_B = 0.5*).

Because these two events are unrelated, learning that Event B occurred gives you a completely fresh, separate piece of information. The total information you receive from observing both events should simply be the sum of their individual contributions:

```text
Information(A and B) = Information(A) + Information(B)
```

If telling you about Event A takes 1 bit, and telling you about Event B takes 1 bit, transmitting both facts together must take *1 + 1 = 2 bits*.

Now observe the mathematical problem this creates:
1. **In probability theory, independent chances multiply:**  
   The probability of both coins landing Heads is *P(A and B) = p_A × p_B = 0.5 × 0.5 = 0.25*.
2. **In communication systems, bit lengths add:**  
   The total message length is *I(A and B) = I(A) + I(B) = 1 bit + 1 bit = 2 bits*.

We therefore need a mathematical function *I(p)* that converts a **multiplication of probabilities** into an **addition of bits**:

```text
I(p_A × p_B) = I(p_A) + I(p_B)
```

In mathematics, what kind of function converts multiplication into addition? **The logarithm:**

```text
log(x × y) = log(x) + log(y)
```

The logarithm is the only family of continuous functions with this property. 

Because probabilities *p* are fractions between 0 and 1, their logarithms are negative. We add a minus sign to ensure information is always a positive number:

```text
I(p) = −log₂(p) = log₂(1 / p)
```

Using base 2 ensures that the units match real-world bits:
* For 1 coin flip (*p = 0.5*): *−log₂(0.5) = 1.0 bit*.
* For 2 coin flips (*p = 0.25*): *−log₂(0.25) = 2.0 bits* (which equals *1 + 1*).
* For 3 coin flips (*p = 0.125*): *−log₂(0.125) = 3.0 bits* (which equals *1 + 1 + 1*).

## 3. Shannon Entropy: The Weighted Average of Uncertainty

Now that we know the bit-length or "surprise" of every individual symbol (*−log₂ pᵢ*), what is the **average information content** per symbol across the entire dataset?

We calculate the expected value (a probability-weighted average) across all *M* possible symbols:

```text
H(p) = E[I(x)] = ∑ pᵢ · (−log₂ pᵢ) = −∑ pᵢ log₂ pᵢ
```

This is **Shannon Entropy** (*H*). It represents the minimum number of binary Yes/No questions needed, on average, to identify an incoming symbol from the source.

## 4. The Two Extremes: Pure Chaos vs. Absolute Certainty

To build a concrete visual intuition for Shannon entropy, consider the two extreme cases of a probability distribution:

![Figure 3: The two boundary conditions of Shannon entropy: complete certainty (H = 0) vs. maximal uncertainty under a uniform distribution (H = log₂ M).](/images/shannon/03_two_extremes.png)

### Extreme 1: Complete Predictability (H = 0)
Suppose an optical sensor is pointing at a pitch-black cavity where *p_black = 1.0* and all other colours have *p = 0*.
```text
H = −(1.0 × log₂ 1.0) = −(1.0 × 0) = 0 bits
```
Because the receiver already knows the outcome in advance, the message contains zero surprise. You do not need to transmit any bits.

### Extreme 2: Maximum Uncertainty / Uniform Distribution (H = log₂ M)
When all *M* symbols are equally likely (*pᵢ = 1/M*), you have zero prior clues:
```text
H = −∑ (1/M) log₂(1/M) = log₂ M
```
For a fair coin (*M = 2*), *H = log₂(2) = 1.0 bit*. For a fair 8-sided die (*M = 8*), *H = log₂(8) = 3.0 bits*.

## 5. The Naive Baseline: Fixed-Length Lookup Tables

In classical uncompressed systems, we map every symbol to a unique binary key in a lookup table *T*.

If we have *M* distinct symbols, how many bits *b* does each symbol require if every code has the exact same length?
```text
2ᵇ ≥ M  ⟹  b = ⌈log₂ M⌉
```

For example, if an alphabet contains 4 symbols (`A`, `B`, `C`, `D`):
- `A` → `00` (2 bits)
- `B` → `01` (2 bits)
- `C` → `10` (2 bits)
- `D` → `11` (2 bits)

A sequence of *N = 100* symbols will always require *100 × 2 = 200 bits*, regardless of whether symbol `A` occurs 99% of the time or 25% of the time. This is where naive encoding wastes bandwidth.

## 6. Shannon's Source Coding Theorem: Optimal Variable-Length Codes

Shannon's Source Coding Theorem [3](#references) establishes that the optimal length *bᵢ* of the binary codeword for symbol *xᵢ* should be inversely related to its probability:

```text
bᵢ = log₂(1 / pᵢ) = −log₂(pᵢ)                    (2)
```

The resulting average code length across the sequence achieves the entropy lower bound:

```text
H(p) = ∑ pᵢ bᵢ = E[b]                            (3)
```

If a symbol appears frequently (e.g., *p_A = 0.5*), Shannon assigns it a 1-bit code (`0`). If a symbol appears rarely (e.g., *p_D = 0.125*), it receives a 3-bit code (`110`). 

Because we encounter the 1-bit code half the time, the total transmitted bitstream shrinks dramatically.

## 8. Looking Forward: From Huffman Trees to Neural Codecs

The principles established by Claude Shannon in 1948 remain the foundation of all modern digital communications. Handcrafted algorithms like Huffman coding and Arithmetic coding approach the Shannon entropy bound for stationary, independent symbol streams.

However, real-world data—such as high-dimensional multispectral satellite imagery or continuous climate simulation fields—features complex spatial, temporal, and spectral correlations that simple independent frequency tables cannot capture.

![Figure 5: Modern Deep Neural Compression architecture for satellite Earth observation data, leveraging non-linear transforms and neural hyperprior entropy models.](/images/shannon/05_neural_compression.png)

In modern **Neural Compression** [1](#references), deep autoencoders replace linear transforms, learning non-linear manifolds that decorrelate high-dimensional features into continuous latents *z*. By pairing these learned transforms with neural entropy models (such as hyperpriors and autoregressive context models), neural codecs approach Shannon's rate-distortion theoretical limits on complex distributions where traditional handcrafted codecs falter.
